# Data requirements (G4EMLOW 8.8, `dna/` subfolder only)

## Chemistry runtime inputs (M7 isolated kernel)
The free-diffusion and isolated two-body IRT kernels require no external runtime dataset: option3 species and reaction TOML are embedded in `dna-chemistry`. To derive option3 pair parameters, the caller must supply the reaction record and validated species properties (diffusivity, radius and charge); sampling also requires two distinct molecule identities, finite positions at a common current time, and a caller-owned RNG. Only supported mobile bimolecular TDC and neutral PDC combinations are executable; first-order and bulk participants and charged PDC are rejected. This requirement does not imply a many-species runtime or consume M6 histories automatically. The source mappings are Geant4 11.4.1 paths documented in docs/04 D.3.

**Policy (decision Q7, revised again):** the ~7 MB subset of `G4EMLOW8.8/dna` listed below is **committed** under `data/dna/` (byte-identical copies; `.gitattributes` disables line-ending conversion). The full 2.1 GB dataset stays outside the repo.
- `data/MANIFEST.toml` (names, sizes, SHA-256, group) is generated by `scripts/make_data_manifest.py` from the full dataset; `scripts/import_data.py <G4EMLOW8.8 dir>` copies exactly those files into `data/` and verifies them. Re-run both when the file list changes.
- Data lookup: env var `G4RS_DATA_DIR` (a directory containing `dna/`) if set, else the repo's `data/`. TOML key `data_dir` overrides both. Point `G4RS_DATA_DIR` at the full `G4EMLOW8.8` to use files outside the subset.
- A test verifies the committed files against the manifest checksums, so cloud sessions and CI can run real-table tests.
- Output metadata always records dataset name/version and the manifest hash.
- Licence: see `data/README.md` (Geant4 Software License attribution).

File names below are from the C++ loaders (`source/processes/electromagnetic/dna/models/src`). `.dat` is appended by the loader where the name has no extension. Existence in your folder is checked by the script, not assumed.

Verified against Geant4 11.4.1 (`rtonneau/geant4` @ `27ea526`). All paths are in `source/processes/electromagnetic/dna/models/src`, `Loader` = `G4DNACrossSectionDataSet` unless stated. ### C. Rust behaviour that differs from the C++ (intentional, tested)
1. Outside `[E_first, E_last]` of a table: `UnsupportedEnergy` instead of the constant clamp of `G4EMDataSet::FindValue`. The model windows lie inside the tables for every file except Melton (table ends at 12.3 eV, window 13 eV, `sigma = 0` there in Geant4); the M2 model layer must handle that explicitly.
2. Malformed tokens, ragged rows and non-finite numbers are errors with file and line (the C++ silently truncates).
3. 2-D lookups: `UnsupportedEnergy` below the first and above the last incident energy (C++ undefined / out-of-bounds); the last energy uses the same `1e-12` protection as Born1 and Ion elastic; `P = 1` uses the last interval; combinations where the C++ reads past a vector end return `UndefinedLookup`.
4. The EOF artefact of the C++ stream loops (one duplicated last entry) is not reproduced; it does not change any lookup.
5. Nothing is applied beyond the file scale: the Sanche factor 2, the `sigma = 1e-30` replacement of a zero Sanche value (`:312, 339`) and the `Rudd` below-table scaling are *model* behaviour for M2/M5.

## M2 usage notes (what the electron models read, checked on the committed files)
- `sigma_elastic_e_champion`, `sigma_excitation_e_born`, `sigma_ionisation_e_born` are used as totals (sum of the 1 / 5 / 5 columns) and as partials for the level/shell choice; table ranges (7.4 eV-1e7, 8 eV-1e6, 8 eV-1e6) cover the model windows (7.4 eV-1 MeV, 9 eV-1 MeV, 11 eV-1 MeV), which `ChampionElastic::new`, `BornExcitation::new` and `BornIonisation::new` assert (`TableDoesNotCoverWindow`).
- Shell thresholds in `sigma_ionisation_e_born` (first non-zero value): shell 0 at 11 eV, shell 1 at 14, shell 2 at 18, shell 3 at 35, shell 4 at 545 eV; at a node below its threshold the table value is exactly 0 and the interpolation returns `1e-300 x scale` (M1 behaviour), e.g. `3e-305 nm^2` for shell 4 at 100 eV; this never selects the shell.
- `sigmadiff_cumulated_ionisation_e_born_hp`: 83 incident energies, block length varies (160 rows at 1 keV, `W` grid in 0.52 eV steps there), `P = 0` plateau below the threshold and `P = 2` padding above the kinematic limit; the lookup keeps the last `W` of each equal `P` (M1). The test oracle in `crates/dna-physics/tests/sampling.rs` rebuilds the inverse CDF from the raw file independently of `dna-data` and agrees (KS) for the open shells at 100 eV (0-3), and for all five shells at 1, 10 and 100 keV.
- `sigmadiff_cumulated_elastic_e_champion_hp`: 101 incident energies, 181 rows per block (1-degree grid), used with exactly the M1 lin-lin lookup; KS agreement with the raw block at five nodes.
- Not read in M2: `sigmadiff_ionisation_e_born` (slow path, docs/09 Q4), Sanche, Melton (M3), all proton files (M5).

- Whitespace-separated plain text, no comments or headers in the committed copies. One file is CRLF (`sigma_ionisation_p_rudd.dat`, 645 lines); two use tabs; spaces otherwise. Parsers split on any whitespace and ignore `\r`.

## M3 notes on data semantics
- **Melton tail (12.3 - 13 eV).** The model window ends at 13 eV, the table at 12.3 eV with value 0. `dna-data` still raises `UnsupportedEnergy` outside the table, as designed in M1; the *model* (`MeltonAttachment`) returns 0 between the last node and 13 eV, reproducing Geant4's constant clamp to the last node, and refuses to be built if the last node were non-zero (`PhysicsError::TableTailNotZero`). Near 4 eV the log-log rule between the zero nodes (0 and 4.2 eV) gives about 1e-304 nm^2 per molecule (the `1e-300` floor times the scale): numerically zero, reproduced.
- **Sanche zero floor.** `1e-30` is replaced in **Geant4 internal units (mm^2)**: 1e-18 nm^2. Applied to every interpolated partial and total value that is exactly 0 (`SancheVibrational::partial_cross_sections`, `total_cross_section`).
- **Sanche sum.** `TotalCrossSection` interpolates the *sum of the nine columns at the nodes*; the table layer's `total()` does the same. The model multiplies by the liquid-phase factor 2 (`SANCHE_LIQUID_PHASE_FACTOR`); Melton and the other models do not.
- Output files of M3: `PhysChemEvent` CSV (`parent_history,kind,level_or_shell,x_nm,y_nm,z_nm,deposited_energy_eV`, header from `dna_physics::physchem::PHYSCHEM_CSV_HEADER`), run JSON schema `geant4-rs/dna-sim/run/v2` (adds the five-process counts, solvation, W, spectra by generation, radial profile, tracks, vibrational levels).

## Chemistry data (M6 A, `data/chemistry/`)
Not Geant4 data files: values transcribed from the C++ source (`G4ChemDissociationChannels_option1.cc`, molecule definitions, `G4DNAElectronHoleRecombination.cc`, `G4EmDNAChemistry_option3.cc`), each with its line number, in four TOML files (`species_option3.toml`, `dissociation_option3.toml`, `physchem_option3.toml`, `reactions_option3.toml`; description in `data/chemistry/README.md`). They are embedded in `dna-chemistry` with `include_str!` (no `G4RS_DATA_DIR` needed). Verification: `scripts/extract_physchem_from_cpp.py` and `scripts/extract_reactions_from_cpp.py` regenerate the machine fixtures from C++ text; `scripts/hand_physchem.py` and `scripts/hand_reactions.py` provide independent checks; `cargo test -p dna-chemistry --test cpp_crosscheck` compares the data to both. A change of Geant4 version means re-running all applicable scripts and diffing.

The 15 species keys in TOML and the extraction fixture match the Geant4 11.4.1 `G4MoleculeTable` keys exactly, including `°OH` and `HO2°`; the crosscheck uses these keys directly. `OH` and `HO2` are legal Rust enum identifiers and legacy ASCII input spellings, not canonical chemistry keys. The four bookkeeping configurations `H2O(B)`, `H3Op(B)`, `OHm(B)`, and `NoneM` are excluded from `Species` and admitted only as typed reaction-table bulk participants. The 72 reactions retain source-order IDs, rate order and source literals; no derived reaction radii or scheduler parameters are stored.

M6 two-stage JSON is schema `geant4-rs/dna-sim/run/v3` and adds `chemistry_data_sha256`, the SHA-256 of the embedded files concatenated in species/channels/parameters/reactions order, plus the physicochemical summary. This is separate from the G4EMLOW manifest hash because the chemistry files are source transcriptions, not G4EMLOW payloads.
